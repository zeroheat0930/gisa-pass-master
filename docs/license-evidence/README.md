# 복원 기출 출처의 라이선스 증거

복원 기출 420문항은 **Life-Journey 블로그**(<https://chobopark.tistory.com>)의
회차별 복원 문제 글에서 가져왔다. 그 글들이 **CC BY 4.0** 으로 공개되어 있었다는
사실을 확인한 시점의 증거를 여기에 보관한다.

**왜 남기는가.** CC BY 는 저작자가 나중에 설정을 꺼도 이미 받은 이용 권한이
소멸하지 않는다(라이선스 제2조 (a)(1), `irrevocable`). 다만 분쟁이 생기면
"그때 정말 그 표시가 있었느냐" 를 우리가 보여야 한다. 그 부담을 없애는 것이
이 폴더의 목적이다.

## 확인 시각

**2026-08-13T08:06:38Z** (UTC)

## 확인된 라이선스

글 하단 CCL 영역에 다음이 표시되어 있다.

```
저작자표시
https://creativecommons.org/licenses/by/4.0/deed.ko
```

**저작자표시(BY) 하나뿐이다.** 비영리(NC)도, 변경금지(ND)도, 동일조건변경허락(SA)도
붙어 있지 않다. 따라서 **상업적 이용과 개작(형식 변환·재구성)이 모두 허용**되며,
우리가 져야 할 의무는 **저작자 표시 하나**다.


## 눈에 보이는가 — 보인다

소스에만 있는 메타데이터가 아니다. 글 맨 아래 `♡ 공감` · `구독하기` 버튼 줄
**오른쪽 끝에 CC 저작자표시(BY) 아이콘**(원 안의 사람 모양)이 렌더링되고,
누르면 `creativecommons.org/licenses/by/4.0/deed.ko` 로 이동한다.

- `ccl_badge_562.png` — 그 버튼 줄을 4배로 확대한 것
- `ccl_context_562.png` — 주변 문맥

CSS 도 확인했다. `.postbtn_ccl{position:absolute;top:0;right:0}` 뿐이고
`display:none` 이나 `visibility:hidden` 이 없다. 스크린리더 전용 클래스
(`screen_out`)는 "(새창열림)" 안내에만 붙어 있고 "저작자표시" 에는 없다.

작아서 놓치기 쉬울 뿐 숨겨진 것이 아니다.

## 티스토리가 자동으로 박은 것이 아니다

블로그마다 값이 다르다 — 주인이 고르는 설정이라는 뜻이다.

| 블로그 | `data-ccl-type` | 실제 라이선스 |
|---|---|---|
| chobopark (Life-Journey) | `2` | **CC BY 4.0** |
| hbase.tistory.com | `5` | CC BY-NC-SA 4.0 |

플랫폼이 강제하는 기본값이라면 모든 블로그가 같은 값이어야 한다.
게다가 Life-Journey 가 고른 것은 비영리(NC)·변경금지(ND)를 **붙이지 않은**
가장 열린 선택지다. 흔한 쪽은 NC 를 붙이는 것이다.

## 표기 보강 — 완료 (v1.8.2)

CC BY 4.0 은 저작자 표시 외에 **라이선스 링크 표시**와 **변경 사실 공지**도
요구한다(제3조 (a)(1)). 현재 표기는 앞의 둘만 충족한다.

| 의무 | 현재 |
|---|---|
| 저작자 표시 | 충족 (`Life-Journey`) |
| 라이선스 종류 명시 | 충족 (`CC BY 4.0`) |
| 라이선스 링크(URI) | **없음** |
| 변경 사실 공지 | **없음** (이미지 → 텍스트/JSON 으로 옮겼다) |

v1.8.1(스토어 출시분)까지는 앞의 둘만 있었다. **v1.8.2 에서 넷을 다 채웠다.**

회차 목록 상단 고지(`round_list_screen.dart` 의 `_notice()`):

```
복원 기출 — 실제 시험을 응시자들이 복원한 문제입니다.
유료 잠금 없이 전체 공개합니다.
출처: Life-Journey 블로그 (chobopark.tistory.com)
라이선스: CC BY 4.0 (creativecommons.org/licenses/by/4.0)
원문의 이미지·표를 앱에서 읽을 수 있게 텍스트로 옮겼습니다.
```

여기에 더해 **라이선스 목록 화면**에도 같은 내용을 등록했다
(`lib/services/license_notices.dart`). 홈 개발자 카드의
`문항 출처 · 오픈소스 라이선스` 줄로 들어간다. 국문·영문 둘 다 넣었다.

지키는 테스트:
- `test/round_list_screen_test.dart` — 화면 고지에서 넷 중 하나라도 빠지면 실패
- `test/license_notice_test.dart` — 라이선스 목록 등록분에 대해 같은 것을 검사

## 오픈소스 라이선스 고지도 함께 넣었다 (v1.8.2)

CC BY 와 별개로, 이 앱이 쓰는 pub 패키지는 대부분 BSD·MIT·Apache 2.0 이고
셋 다 **배포물에 저작권 고지와 라이선스 사본을 포함할 것**을 조건으로 건다.
v1.8.1 까지 앱에 그 화면이 아예 없었다 — 실제 미이행 상태였다.

`showLicensePage` 를 여는 입구를 홈 개발자 카드에 넣어 해결했다
(`lib/widgets/license_notice_row.dart`). Flutter 가 빌드 때 모아둔 패키지
라이선스가 그대로 나온다.

## 남은 회색지대 (법적 판단이 필요한 것)

기술적으로 처리할 수 있는 것은 위까지다. 아래는 판단의 영역이라 남겨둔다.

- **원 시험문제의 권리는 한국산업인력공단에 있다.** 블로그 주인이 라이선스를
  걸 수 있는 범위는 본인 기여분(수집·정리·해설)까지다. 시중 기출문제집과
  복원문제 블로그·앱이 공통으로 안고 있는 영역이며 이 앱만의 문제가 아니다.
  복원 문항은 응시자 기억에 의한 재구성이라 원문 그대로가 아니라는 점이
  실무상 근거가 되어 왔다.
- **앱 아이콘(`assets/icon.png`)의 출처가 저장소에 기록되어 있지 않다.**
  직접 만든 것인지, 생성형 도구 결과인지, 스톡 이미지인지 확인해 여기에
  적어둘 것. 스톡이라면 라이선스 종류(상업적 이용 가능 여부)를 함께 남긴다.

## 우리가 지고 있는 의무

앱은 복원 기출 회차 목록 상단에 다음을 항상 노출한다.

```
출처: Life-Journey 블로그 (CC BY 4.0)
```

`lib/screens/round_list_screen.dart:247`. 이 표기가 사라지면
`test/round_list_screen_test.dart` 가 실패한다.

**AI 예상 문제 목록에는 이 표기를 띄우지 않는다.** 거기 띄우면 AI 문항까지
그 블로그에서 온 것처럼 읽혀 오히려 사실과 달라진다.

## 형식을 바꿨다고 의무가 사라지지 않는다

원문은 이미지로 올라온 문항이 많아 우리가 읽어서 JSON 으로 옮겼다. 이것은
**복제·개작**이지 새 저작물의 창작이 아니다. 표현을 그대로 옮긴 이상 형식이
PNG 에서 JSON 으로 바뀐 것은 저작권 판단에 영향을 주지 않는다. 특히 **해설
문장**은 블로그 운영자가 직접 쓴 것이라 저작물성이 뚜렷하다.

다행히 CC BY 는 개작을 명시적으로 허용한다. 표시만 유지하면 지금 형태 그대로
상업적으로 써도 문제가 없다. **표시를 지우는 순간에만** 라이선스가 소멸해
무단 이용이 된다(제6조 (a)).
